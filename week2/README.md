# Week 2: 소리로 이미지 보내기

노트북 A의 스피커로 "삐-뽀-삐" 소리를 내서 이미지를 보내고, 노트북 B의 마이크로 받아서 이미지를 되살립니다.

```
[노트북 A]  이미지 -> (1주차) Encoder+양자화 -> 비트 0101... -> 소리 -> 스피커
                                                                    ~~~ 공기 ~~~
[노트북 B]  마이크 -> 소리에서 비트 읽기 -> 비트 0101... -> (1주차) Decoder -> 이미지
```

이미지 ↔ 비트 변환은 함께 들어 있는 `week1/` 폴더(1주차 정답 + 학습된 모델)를 그대로 씁니다.
송수신 프로그램(`tx.py`, `rx.py`, `loopback.py`)은 완성되어 있고,
여러분은 **`modem.py`에서 "비트 ↔ 소리"의 핵심 부분 5곳**을 직접 만듭니다.

|---|---|
| **샘플링 주파수 fs** | 1초에 소리를 몇 개의 숫자로 나타내나 (48,000) |

## 단계 0. 준비: 비트를 소리로 보낸다는 것

스피커는 숫자 배열을 받아서 그 모양대로 진동판을 움직입니다.
1초에 48000개 숫자를 보내면(샘플링 주파수 `fs = 48000`) 그게 1초짜리 소리가 됩니다.

그러니까 "비트를 소리로 보낸다" = **비트를 숫자 배열(파형)로 바꾸는 규칙**을 정하는 것이고,
받는 쪽은 녹음된 숫자 배열을 보고 그 규칙을 거꾸로 적용하면 됩니다.

우리가 쓸 규칙은 **BFSK** (Binary Frequency Shift Keying):

- 비트 0 → 3000 Hz 음 (조금 낮은 "삐")
- 비트 1 → 5000 Hz 음 (조금 높은 "삐")
- 한 비트는 1/200초 동안 (= 200 baud, 샘플 240개)

`modem.py` 맨 위의 `add_modem_args`에서 이 숫자들(`--f0`, `--f1`, `--baud` ...)을 확인해 보세요.

## 단계 1. 비트 → 소리 (`fsk_modulate`, TODO 1)

**읽기.** 코드에는 이미 "샘플마다 어떤 주파수를 낼지"를 적은 배열 `freq`가 만들어져 있습니다.
이제 이 주파수대로 소리 나는 사인파를 만들어야 합니다.

주파수가 f로 일정하면 사인파는 `sin(2π·f·t)`입니다. 괄호 안의 `2π·f·t`를 **위상**이라고 부르고,
위상은 **샘플 하나마다 `2π·f/fs`씩 늘어납니다.** 주파수가 중간에 바뀌어도 이 규칙은 그대로입니다.
그러면 n번째 샘플의 위상은 어떻게 구할까요? `modem.py`의 TODO 1 주석을 읽고 채워 보세요.

**확인.**
```

python explore_week2.py 1
```
- 그림: 파형과 스펙트럼 + `results/explore_step1.wav` (더블클릭해서 들어 보세요!)

  채점은 350 baud로 하기 때문입니다. explore 1 그림 맨 아래(350 baud 확대)가 빨간색 **JUMP!** 이면 그 경우입니다.

## 단계 2. 소리 → 비트 (`fsk_demodulate`, TODO 2)

**읽기.** 받은 소리를 비트 길이(240샘플)씩 자르면, 조각마다 "3 kHz에 가까운지 5 kHz에 가까운지"만
판단하면 됩니다. 그런데 실제로 받은 소리에는 잡음이 섞여 있어서 눈으로 봐서는 알 수 없습니다.

**소리 x에 주파수 f 성분이 얼마나 들어 있는지** 재는 방법:

```
C = Σ x[n] · cos(2π f t[n])      (x 와 cos 파형을 샘플마다 곱해서 전부 더함)
S = Σ x[n] · sin(2π f t[n])      (sin 으로도 똑같이)
크기(f) = √(C² + S²)
```

- x가 주파수 f의 사인파면 곱한 값이 계속 같은 부호로 쌓여서 커지고, 다른 주파수면 +와 −가 서로 지워져서 거의 0이 됩니다.
- cos와 sin을 둘 다 쓰는 이유: 받은 소리가 언제 시작했는지(위상)를 모르기 때문. √(C²+S²)는 위상과 상관없이 같습니다.
- 3 kHz 크기와 5 kHz 크기를 각각 재서 더 큰 쪽을 고르면 끝입니다.
- (복소수를 아는 사람: 위 계산은 `|Σ x[n]·e^(−j2πft[n])|`, 즉 푸리에 변환을 한 주파수에서만 계산한 것과 같습니다.)

`seg`는 (비트 수, 샘플 수) 모양의 2차원 배열입니다. for 문으로 한 행씩 계산해도 되고,
`np.sum(..., axis=1)`로 행마다 한 번에 더해도 됩니다. 자세한 설명은 TODO 2 주석에 있습니다.

**확인.**
```
python check_week2.py 2
python explore_week2.py 2
```
- 그림: SNR 0 / −13 / −16 dB에서 비트를 몇 개 틀리는지, 그리고 SNR별 BER 표가 화면에 나옵니다.
- **SNR −8 dB(잡음이 신호보다 6배 셈)에서도 거의 안 틀립니다.** 한 비트를 240개 샘플로 판단하니 잡음이 서로 상쇄되기 때문입니다.

## 단계 4. 헤더를 3번 보내고 다수결 (`majority_header`, TODO 4)

**읽기.** 긴 데이터를 한 번에 보내지 않고 256비트씩 **프레임**으로 잘라 보냅니다.
각 프레임 앞에는 "몇 번째 프레임인지, 길이가 얼마인지"를 적은 **헤더**(32비트)가 붙습니다.

헤더가 틀리면 그 프레임의 데이터를 어디에 놓을지 몰라서 프레임을 통째로 버려야 합니다.
그래서 헤더만 **3번 반복**해서 보내고, 받는 쪽은 위치마다 다수결로 정합니다.

**확인.** (그림 대신 화면에 출력됩니다)
```
python check_week2.py 4
python explore_week2.py 4
```

## 단계 5. 프레임 조립 (`build_frame_bits`, TODO 5)

**읽기.** 프레임 하나의 비트 순서는 이렇습니다.

```
| chirp | 헤더 | 헤더 | 헤더 | 데이터(payload) 256비트 | CRC 16비트 |
          <--- 3번 반복 --->
```

**CRC**는 데이터를 요약한 16비트 값입니다. 받는 쪽이 같은 계산을 해서 값이 다르면
"이 프레임에 에러가 있다"는 걸 알 수 있습니다.
(에러가 있어도 데이터는 버리지 않고 씁니다. 1주차에서 봤듯이 비트 몇 개가 틀려도 이미지는 대부분 복원됩니다.)

chirp는 소리를 만들 때 따로 붙으므로, 여기서는 **헤더×3 + payload + CRC** 비트만 이어 붙이면 됩니다.

**확인.**
```
python check_week2.py 5
python explore_week2.py 5
python explore_week2.py 5 --frame_bits 64     # 프레임을 짧게 하면 효율은?
python check_week2.py                          # 전체: 18/18, "모두 통과!" 이면 완성
```

## 단계 6. 컴퓨터 안에서 전체 연결해 보기 (스피커 없이)

`loopback.py`는 소리가 공기를 지나며 겪는 일(작아짐, 늦게 도착, 메아리, 잡음, 두 컴퓨터의 시계 차이)을
흉내 낸 뒤 여러분의 모뎀으로 받아 봅니다. **SNR마다 결과 그림**이 `results/loopback_snr{SNR}.png`로 저장됩니다.
기본값과 다른 옵션을 주면 파일 이름에 붙습니다 (예: `loopback_snr-8_baud400.png`, `loopback_snr-8_inter.png`).

```
python loopback.py                                  # SNR 10, 0, -5, -8, -10 dB
python loopback.py --snr -8 -9 -10 -11 -12          # 에러가 생기기 시작하는 구간을 자세히
python loopback.py --interleave                     # 인터리빙 (loopback은 한 번만 붙이면 됨)
python loopback.py --snr 10 --ppm 500 2000          # 두 컴퓨터 시계 차이가 크면?
python loopback.py --baud 400 --snr 0 -5 -8         # 더 빠르게 보내면?
python loopback.py -h                               # 모든 옵션
```

출력 읽는 법:
- **chirp 찾음 N번 → 헤더까지 읽은 프레임 8/8**: 프레임 시작을 몇 번 찾았고, 그중 헤더까지 읽은 게 몇 개인지.
  못 읽은 프레임은 그 자리 이미지가 회색이 됩니다. (chirp 자체를 못 찾았는지, 찾았는데 헤더가 깨졌는지 구분 가능)
- **CRC 실패**: 받기는 했지만 비트가 틀린 프레임 수 (그래도 데이터는 씁니다).
- **BER**: 받은 비트 중 틀린 비율. 2048비트 중 2개 틀리면 9.8e-04. (프레임을 하나도 못 받으면 계산할 수 없음)
- **PSNR**: 이미지 화질 (1주차와 같음).

## 단계 8. 진짜 소리로 주고받기

**받는 쪽을 먼저** 시작하고, 녹음이 시작되면 보내는 쪽을 실행합니다.

```
# 받는 쪽 (노트북 B): 녹음 시간은 tx.py 가 알려 준 시간 (기본 26초)

# 보내는 쪽 (노트북 A)

```

- **장치 두 개로 하세요.** 한 노트북에서 스피커와 마이크를 같이 쓰면, 노트북 마이크의 **에코 제거** 기능이
  자기 스피커 소리를 지워 버려서 대부분 실패합니다. 노트북이 한 대뿐이면 `tx.wav`를 **휴대폰으로 옮겨서

- 두 장치 모두 이 저장소와 `data/`(CIFAR-100)가 있어야 합니다 (휴대폰 재생이면 받는 노트북만).
  받는 쪽은 같은 `--index` 이미지로 정답을 만들어 BER과 PSNR을 계산합니다.
- `--baud`를 바꾸면 송신 길이도 바뀝니다 (100 baud는 약 32초 → `--record 41`). **tx.py가 출력하는 `--record` 시간**을 쓰세요.
- 실패하면 rx.py가 출력하는 **`[진단]`** 줄을 읽어 보세요.
  - 소리가 너무 작음 / chirp를 못 찾음 / chirp는 찾았는데 헤더를 못 읽음 (에코 제거 의심) / 녹음이 너무 짧음 / 옵션 불일치
- 소리가 안 잡히면: 볼륨을 올리고 가깝게(30 cm 정도) 두고, `python -m sounddevice`로 마이크 번호를 확인해서
  `--device 번호`를 붙여 보세요. Windows 설정 → 개인 정보 → 마이크에서 "데스크톱 앱의 마이크 접근"이 켜져 있어야 합니다.
- 에러가 많으면: 양쪽에 똑같이 `--baud 100` (더 느리게, 녹음 시간도 늘리기).

   힌트: (1) 400 baud면 한 비트가 240개가 아니라 120개 샘플 → 판단에 쓰는 샘플이 절반.
   (2) 한 비트는 2.5 ms인데, 시뮬레이션의 메아리는 3 ms 늦게 도착합니다.
4. **왜 프레임마다 chirp를 다시 붙일까?** 두 컴퓨터의 시계가 50 ppm 다르면,
   17.5초 동안 몇 샘플이 어긋나나? (한 비트 = 240 샘플)
